\resumeentry{GPU-Accelerated Database Systems and Matrix-Native Query Processing}
  {Jun 2026 -- Present}
  {Python, PyTorch, CUDA, SQL, cuSPARSE}
\begin{itemize}
  \item Developing a correctness-validated Python/PyTorch prototype that represents relational query dataflows with tensor and matrix primitives; studying fusion across filtering, joins, grouping, and aggregation, with runtime evaluation ongoing.
  \item Implemented TQP-style tensor plans for all \textbf{22 TPC-H queries}, including equijoins, semi-joins, anti-joins, correlated subqueries, grouping, sorting, dictionary-encoded predicates, and result materialization.
  \item Built deterministic correctness validation against canonical SQL outputs and regression tests for SQL empty-aggregate behavior in Q14, Q15, Q17, and Q19.
  \item Reproduced TCUDB microbenchmark patterns Q1, Q3, and Q4; implemented sparse COO membership-matrix joins in PyTorch and substituted them into TQP query plans.
  \item Characterized join representations at TPC-H scale factor 10 (approximately 10 GB of generated data), finding many membership products below 0.04\% density; measured encoding, sparse-format construction, multiplication, extraction, and remaining operations separately.
  \item Built paired end-to-end benchmarks from staged GPU tensors to final query results. Original TQP plans were faster in all \textbf{13 valid comparisons}, showing that representation construction frequently outweighed the benefits of the sparse matrix formulation.
  \item Profiled Q1--Q20 and Q22 at SF10, and Q21 at SF2, on an RTX 5090 using PyTorch Profiler, Nsight Systems, Nsight Compute, and roofline analysis; measured empirical baselines of 63.029 TFLOP/s for FP32 GEMM with TF32 disabled and 1.575 TB/s for device bandwidth.
  \item Identified bottlenecks in scatter/atomic aggregation, sorting, and gather/index operations; diagnosed Q1 contention on a small number of aggregation bins and DRAM-bound element-wise operations in Q1 and Q3.
\end{itemize}

\resumeentry{RTBoost: Ray-Tracing-Based Gradient-Boosted Tree Inference}
  {Jan 2026 -- Jun 2026}
  {OptiX, CUDA, XGBoost \textbar\ Collaborator: Andy Li}
\begin{itemize}
  \item Designed a mapping from gradient-boosted tree inference to ray-tracing acceleration structures, representing tree regions with axis-aligned bounding boxes (AABBs) and using ray traversal for batched inference.
  \item Implemented model processing, workload generation, training, benchmarking, and early system components; collaborated with Andy Li, who implemented the final OptiX algorithm component.
  \item Designed controlled workloads and evaluated synthetic three-dimensional forests with depths up to 12 and approximately 400 trees on RTX 4070, RTX 4090, and RTX 5090 GPUs.
  \item Validated RTBoost3D on SSMCR, containing 110,204 three-dimensional points, and evaluated SUSY-3D; tested batched launches subject to OptiX launch-dimension limits.
  \item Used Nsight and memory-trace analysis to investigate memory coalescing, control flow, traversal efficiency, and AABB-fetch stalls; identified invalid timings caused by failed kernel launches.
  \item Co-designed and evaluated a layout using a reusable base AABB and transformed instances. Same-device evaluations remained slower than XGBoost; documented the limitations and paused the project after finding no robust performance advantage.
\end{itemize}

\resumeentry{RTSpMSpM: Harnessing Ray Tracing for Efficient Sparse Matrix Computations}
  {Sep 2023 -- Sep 2025}
  {\textbf{ISCA '25} \textbar\ First author and conference presenter \textbar\ OptiX, CUDA, C++, Python}
\begin{itemize}
  \item Designed an algorithm that maps sparse matrix--matrix multiplication (SpMSpM) to ray-tracing operations, enabling NVIDIA RT Cores to accelerate non-graphics sparse computation.
  \item Led development of the OptiX/CUDA library implementing the mapping and achieved \textbf{up to 1.85$\times$ speedup over cuSPARSE}.

  \item Created controlled sparse-matrix workload generators with diagonal, scattered, and corner-concentrated nonzero patterns to study input-layout sensitivity, traversal behavior, and matrix-reordering effects.
\end{itemize}
